# Information in Logic — explainers

Five scroll-driven, zero-dependency explainers dramatizing mechanisms from
the paper. No build step, no libraries, no CDN calls — just
`index.html` / `style.css` / `script.js` per piece.

- [`shannon-extension/`](shannon-extension/) — "Reasoning Amplifies
  Information": Shannon's classical model of communication stops the
  instant a message is decoded. This piece draws the one stage the paper
  adds back in: a receiver who reasons over what's received.
- [`entailment/`](entailment/) — "What a Sentence Means": A sentence's
  meaning is a kernel — the set of possible worlds consistent with it. A
  weaker sentence's kernel contains a stronger one's, entailment as literal,
  visible containment: why a stronger sentence's kernel looks smaller.
- [`no-need-to-know/`](no-need-to-know/) — "No Need to Know": Alice doesn't
  know what Bob already knows. She hashes her kernel into a short index; Bob
  rules out same-bin "confounders" using his own background knowledge.
- [`less-is-more/`](less-is-more/) — "Less is More": Alice knows exactly what
  she wants Bob to end up able to prove. A short, pre-agreed list of
  candidate kernels lets her send less than either obvious strategy, while
  Bob ends up able to prove more than was strictly required.
- [`incorrect-information/`](incorrect-information/) — "The Price of
  Incorrect Information": Being merely outdated costs little to fix — but a
  confidently wrong belief costs far more, and the gap only grows as it
  becomes more confident.

Each piece has its own README with full implementation notes and development
history.

[`blog-combined/`](blog-combined/) weaves all five into one continuous,
narrated page instead of five separate ones. Its own `index.html` is a
committed, generated file — readable/viewable with no build step, same as
everything else here — but it shouldn't be hand-edited: it's generated by
`blog-combined/build.js` (plain Node, zero dependencies) from
`blog-combined/content.js` (the connective prose and page order) plus each
piece's own `index.html` above, read fresh off disk. After editing either
of those, regenerate with `node build.js` from inside `blog-combined/` (see
that file's own comments, including the `PIECE_DIR_PREFIX` this repo needs
since its own piece directories aren't `explainer-`-prefixed the way the
IBM research monorepo's are) and commit the result.
